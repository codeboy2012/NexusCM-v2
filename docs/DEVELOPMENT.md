# Development

## Philosophy

Keep the project modular.

Avoid tightly coupling services.

Every feature should be independently testable.

---

## Branches

main
: Stable development

dev
: Active development

feature/*
: Individual features

hotfix/*
: Emergency fixes

---

## Commit Style

Examples:

feat: add MAS configuration

fix: repair Synapse startup

docs: update architecture

refactor: simplify installer

---

## Development Workflow

1. Create a branch
2. Implement feature
3. Test locally
4. Open Pull Request
5. Review
6. Merge

---

## Coding Standards

- Use consistent formatting
- Keep functions small
- Prefer readability
- Document complex logic
